PHASE 4: SPEED (same files, same install)
Nothing changes on screen. What changes is how much the server reads and waits.

1. No waiting in line for screens that only read
   The game screen, the workout screen, the nutrition questionnaire, the streak screen and the staff
   nutrition list no longer wait for the "one at a time" lock. If such a screen needs to write
   (first game of a new player, a missing tab, leaderboard hide changed), it goes back in line and
   does it exactly as before. Writes still go one at a time.

2. Smarter cache (2 minutes, like before)
   Before: any write cleared every cached screen of every person.
   Now: expenses, recurring expenses, client notes, flags, physio intake, files and insurance claims
   only reload the staff screens; a client's own change (game, streak, goal, profile, workout log,
   nutrition) only reloads the screens that show that client (a parent who sees the child too).
   Sales, bookings, attendance, cancels and payments still reload everyone, like before.
   The cache versions are kept in the cache, so the APP_VER Script Property is no longer written.

3. Fewer full sheet reads
   * Client boot reads only the photos of the people on that screen (before: every client's photo).
   * Opening the game reads your own row; the leaderboards come from a 1 minute cache that is
     renewed after every run save. A manual edit in the CORNICHE RUN tab shows within 1 minute.
   * New package / expense rows are written in a few calls instead of one call per cell
     (same cells, same formats, same formulas). ID scans read only the filled rows.
   * A 1:2 cancel and a session change recount all their packages in one pass.

4. Daily quotas
   * The client sign in secret, the staff keys and the deleted accounts list are read from the cache
     (10 minutes) instead of Script Properties on every request. Changing them (sign everyone out,
     new staff link) is seen at once.
   * An email that is not a client is remembered 2 minutes (guests asked on every screen).
     A client created from a confirmed lead is seen at once.
   * If Gmail's daily email limit is reached, the sign in screen says so clearly instead of an error.

5. One change you will notice (on purpose)
   Romy gets at most one WhatsApp per client every 10 minutes for app requests. Every request is
   still saved and shows in her To do list. CallMeBot bans numbers that receive too many messages.

Tests: 243 checks (the 192 from before plus 51 new ones for the speed work), all passing.

 * sw.js is the offline cache. To switch it off for everyone: set OFF = true in sw.js and push.
